### Day build

**You own the queue and the verdicts. Builders own their tickets. Nothing merges, and every verified PR waits for the Evening session.**

This starts when Alex runs `claude attach night-<YYYY-MM-DD>`, reads the morning brief and types "Go" in the night session. That same session runs this playbook, so it already knows the skills directory, the project and the approved list. If that session is gone, a fresh lead session reads the saved list from the night run's decision log, whose path is in the brief. Conventions, the claim rule and the two-layer contract are in `linear.md`. The team is whichever team owns the project, and states are mapped by type: Ready is `unstarted`, In Progress is `started`, and In QA is the state Linear calls In Review. Run **Autopilot-stack** over the queue in step 2, which comes from the brief's Linear tickets instead of GitHub. The overrides in step 3 go into every builder's kickoff. `worker.md` makes them the whole bar: "The bar in your kickoff is the whole bar."

1. **Create the tickets.** Run **to-tickets** in create mode with the approved list from the brief, which the attached session still holds. Report the identifiers and blocking edges. Then write the identifiers of the created and edited tickets and of the approved Backlog promotions into the night run's decision log, beside the carried-over identifiers that Night plan wrote there. The Evening session and a fresh day build session use this list to tell the cycle's tickets from any other.
2. **Build the queue.** The queue holds only the tickets in the approved brief: the slices step 1 created or edited, the tickets marked `promote <id> from Backlog` that Alex approved, and the carried-over tickets the brief lists, as `night-plan.md` step 6 defines them. Each one must be Ready, not blocked, not In Progress and unassigned. Read the project's Ready, unassigned tickets with `list_issues`, every page, as `linear.md` says. Leave alone a Ready ticket that the brief does not list. If Linear's blocked-by data looks stale, trust the PR state and track blocking in `keel-store`, per `linear.md`. Add a ticket from the brief to the queue when its last blocker reaches In QA.

   When a fresh session runs Day build because the night session died, a ticket the decision log lists that is In Progress without `needs-alex` was claimed by the dead session and has no builder. First run `claude agents --json` and confirm the night session is not listed. If it is listed, it is alive: attach to it instead of taking over. Otherwise keep each such ticket's claim and add it to the queue. Step 3 dispatches it on its PR's branch, or on the branch the dead session pushed. For work left only in the dead session's worktree, follow `playbooks/session-pickup.md` first.
3. **Dispatch one builder per ticket.** Read the ticket's fix-round count from its comments ("fix round n of 2"), counting only rounds after the latest "fix rounds reset by Alex" comment, and put the remaining rounds in the kickoff. Claim the ticket first: set In Progress and the assignee. Then spawn one `keel:ponytail` with `isolation: "worktree"`. A ticket that already has a PR gets a fresh `keel:ponytail` on that PR's branch, not a new branch. Each kickoff opens with `Read <skills dir>/lead/worker.md before anything else.`, links the ticket and its `Spec:` document, and carries the two-layer contract from `linear.md`: the file paths, which you find by reading the code now, the base branch, and the stop at verified. It states these overrides in so many words:
   - **Merge policy.** Open the PR ready per `playbooks/opening-a-pr.md`, babysit it to green, and stop. Never merge.
   - **Discovered work.** Report anything found outside the ticket to the lead in your final report. Never open a PR for it and never fix it. This overrides `autonomous-run.md` step 4 and the "fix it in the next round" line in **principle-never-block-on-the-human**.
   - **Fix cap.** Do your one assigned fix and report. The kickoff states how many fix rounds remain. You never count fix rounds and never add `needs-alex`; the lead does. This overrides "A plateau is not a stop."
   - **Linear.** Writes to this project (claim, state moves, comments) count as part of the run, so `worker.md`'s stop before a message to someone outside the run does not apply to them.
   - **Scope.** The ticket's pass predicates and out-of-scope list are the whole job.
4. **Collect discoveries.** As each builder reports, append its discovered items to the `Discovered work: <project>` document, with the ticket, the finding and the evidence. You alone write it. Create it if it does not exist.
5. **Review once.** When every started builder has reported a PR or stopped, spawn one `keel:critic` pass over all of the day's PRs together, not one swarm per PR. Give it the correctness lens, with each ticket's pass predicates in the brief next to its PR, and ask it to run each predicate on the PR's head. Add a second critic only where a PR moves a security or authority boundary. A finding goes to a fresh `keel:ponytail` on the same branch as a fix round. You count the rounds per ticket, counting only rounds after the latest "fix rounds reset by Alex" comment, at most two, because you run the re-reviews that decide whether a fix failed. Before each fix, write the ticket comment "fix round n of 2: <reason>". Re-review only the PRs whose patch changed. When the second fix round fails re-review, add `needs-alex`, leave the ticket In Progress, comment what failed, and take it off the queue. Rounds written at 7 PM for QA failures count toward the same two, and a "fix rounds reset by Alex" comment starts the count again.
6. **Verify and move.** A PR is verified when its predicates pass at its current head and its CI is green. Move a verified PR's ticket to In QA and post the verdict, `PASS` or `PASS+NOTES`, and the critic's report for that PR as a PR comment. A ticket at its cap carries `needs-alex`, which you added in step 5, and stays In Progress.
7. **Stop** when the step 2 queue is empty and every started PR is verified or handed back, or at 7 PM, whichever comes first. At 7 PM, let a builder that is mid-fix finish its commit, move nothing else, and list its ticket as unfinished. The Evening session releases it. Never merge, and never promote a Backlog ticket beyond the `promote <id> from Backlog` lines Alex approved with his Go.

**Reply:** each ticket with its PR, verdict and state, the tickets on `needs-alex`, the items appended to the discovered-work document, the Ready tickets the brief did not list, and what is unfinished. Per **ketchup**, this is the list Alex works from at 7 PM.
